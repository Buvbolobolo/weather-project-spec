ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

Название проекта: WeatherScope

Тип продукта: Progressive Web Application (PWA) / Веб-сервис

Цель: Разрабатываемый проект будет представлять собой веб-сервис анализа погоды, позволяющий получать пользователям актуальные погодные данные, прогнозы, погодные карты и персональные уведомления (алерты)

Основной источник данных: OpenWeather API (с возможностью расширения другими провайдерами).
Ключевое отличие: Фокус на координатах (геоточках), а не только на городах, что позволяет получать точные данные для любого места.

3. АНАЛИЗ ПОЛЬЗОВАТЕЛЕЙ (ГРУППЫ)
================================================================================

ГРУППА 1: Городские жители (Urban Residents)
Описание: Люди, которые живут в городе и используют сервис для повседневного планирования. Сюда же входят люди с активным образом жизни (велосипедисты, бегуны, курьеры).

Контекст: Ежедневно, утром перед выходом из дома или в течение дня.

Потребности: Быстро узнать погоду в своём районе или конкретной точке (парк, стадион, офис). Получить уведомление, если погода ухудшится во время прогулки/тренировки.

Ключевые функции: Текущая погода, почасовой прогноз на 24 часа, сохранение точек на карте, базовые алерты (дождь, ветер).

ГРУППА 2: Планировщики поездок (Travel Planners)
Описание: Люди, которые планируют отпуск, командировку или путешествие в другой город/регион и хотят знать погоду заранее.

Контекст: Периодически, перед поездкой (за несколько дней или недель).

Потребности: Увидеть прогноз на 5-10 дней вперёд. Сравнить погоду в нескольких точках маршрута. Понимать общие тенденции (будет ли тепло, будут ли дожди в дни поездки).

Ключевые функции: Прогноз на 5+ дней, сохранение нескольких локаций (маршрут), визуализация температурных трендов.

ГРУППА 3: Метеозависимые пользователи (Weather-Dependent Users)
Описание: Люди, чья деятельность или самочувствие сильно зависят от погодных условий (аллергики, люди с хроническими заболеваниями, организаторы мероприятий, фермеры).

Контекст: Постоянно, несколько раз в день, требуют детального контроля.

Потребности: Максимально подробная информация (давление, влажность, УФ-индекс, качество воздуха). Гибкая настройка алертов под конкретные пороги значений.

Ключевые функции: Расширенные метрики, кастомные алерты (любой параметр + любой порог), история изменений погоды.

5. Как турист, я хочу сохранить несколько точек на карте (маршрут), чтобы быстро переключаться между ними и сравнивать погоду в разных местах.

6. Как планировщик, я хочу видеть температурный тренд по дням (мин/макс), чтобы выбрать наилучшие даты для поездки.

9. Как внимательный пользователь, я хочу иметь возможность задать любой порог для любого параметра погоды, чтобы получать уведомления только когда это действительно важно для меня.

5. ПОЛЬЗОВАТЕЛЬСКИЕ СЦЕНАРИИ (USER JOURNEYS)
================================================================================

СЦЕНАРИЙ 1: Регистрация и первое использование
Пользователь открывает сайт.
Сайт запрашивает разрешение на доступ к геолокации.
Пользователь нажимает «Разрешить».
Frontend отображает погоду для текущих координат.
Пользователь пытается сохранить точку -> появляется окно «Войдите или зарегистрируйтесь».
Пользователь вводит Email и пароль -> нажимает «Зарегистрироваться».
Backend создаёт запись в базе, возвращает JWT Token.
Frontend сохраняет токен и успешно сохраняет точку в базу.

СЦЕНАРИЙ 2: Получение прогноза и работа с картой
Пользователь переходит на вкладку «Карта».
Выбирает слой «Осадки».
Внизу экрана появляется временная шкала (Timeline) с шагом 1 час.
Пользователь перетаскивает ползунок на «+3 часа».
Frontend запрашивает новые тайлы карты для выбранного времени.
Карта обновляется, показывая прогноз осадков на будущее время.
Пользователь кликает на точку -> видит сводку -> нажимает «Сохранить».

СЦЕНАРИЙ 3: Настройка и получение алерта
Пользователь переходит в раздел «Мои алерты».
Нажимает «Создать новый алерт».
Выбирает сохранённую локацию, параметр (например, «Ветер»), условие и значение.
Нажимает «Сохранить».
Backend запрашивает разрешение на браузерные уведомления.
Backend сохраняет правило и подписывает устройство на Push-уведомления.
При совпадении условия пользователь получает Push-уведомление в систему даже при закрытом браузере.

6. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
================================================================================

FRONTEND (Клиентская часть)
Технологии: React, TypeScript, PWA (Service Workers), Leaflet/Mapbox

Авторизация
Форма регистрации (Email, Пароль, Повтор пароля)
Форма входа (Email, Пароль)
Выход из аккаунта (очистка токена)
Хранение JWT токена в localStorage/secure cookie

2. Главный экран (Dashboard)
Отображение текущей температуры (фактической и «по ощущениям»)
Крупная иконка погодных условий
Блок «Детали»: Влажность, Давление, Ветер, УФ-индекс
Кнопка «Обновить»

3. Почасовой прогноз
Горизонтальный скролл-лист на 24-48 часов
Данные: Время, Температура, Иконка, Вероятность осадков %
Загружается из отдельного API эндпоинта (Hourly Forecast)

4. Прогноз на 5 дней
Вертикальный список по дням
Данные: Дата, Мин/Макс температура, Основная погода дня
Загружается из отдельного API эндпоинта (5-Day Forecast)

5. Интерактивная карта
Слои: Температура, Осадки, Облачность, Ветер
Time-slider: Ползунок времени с шагом 1 час
Клик по карте: Открывает пин с краткой сводкой и кнопкой «Сохранить точку»
Отображение сохранённых точек пользователя на карте (пины)

6. Управление локациями
Список сохранённых точек (Название, Координаты, Последнее обновление)
Редактирование названия точки
Удаление точки
Доступно только после входа (авторизации)

7. Система алертов
Запрос разрешения на браузерные уведомления (Push API)
Создание правила: Локация -> Параметр -> Условие -> Порог
Список активных алертов
История сработавших уведомлений

8. PWA функции
Service Worker для кэширования статических ресурсов
Offline режим: отображение последних закешированных данных
Push Notifications для алертов

BACKEND (Серверная часть)
Технологии: Python (FastAPI/Django), PostgreSQL, Redis (кэш), Celery (задачи)

API Шлюз (Proxy)
Сервер выступает посредником между Frontend и OpenWeather API
Скрытие ключей: API ключи провайдера не хранятся на клиенте
Лимитирование: Rate Limiting для защиты от злоупотреблений

2. Кеширование данных
Ответы от погодного API кэшируются в Redis на 10-60 минут
При запросе тех же координат данные отдаются из кэша
Ключ кэша формируется из: координаты + тип данных + время

3. Аутентификация
Регистрация пользователя (хеширование пароля bcrypt/argon2)
Логин с выдачей JWT Token (срок жизни 24 часа)
Refresh Token для продления сессии
Middleware для проверки токена на защищённых эндпоинтах

4. Управление данными пользователей (База данных)
Таблица Users: id, email, password_hash, created_at
Таблица UserLocations: id, user_id, lat, lon, name, created_at
Таблица Alerts: id, user_id, location_id, parameter, condition, threshold, is_active
Таблица PushSubscriptions: id, user_id, endpoint, keys (для Web Push)

5. Сервис уведомлений (Worker)
Фоновая задача (Celery Beat), запускается раз в 30-60 минут
Проверяет условия алертов для всех активных пользователей
При совпадении условия -> отправка Push-уведомления через Web Push Protocol (VAPID)
Логирование отправленных уведомлений

6. Эндпоинты API
POST /auth/register — регистрация
POST /auth/login — вход, получение токена
GET /weather/current?lat=&lon= — текущая погода
GET /weather/hourly?lat=&lon= — почасовой прогноз
GET /weather/daily?lat=&lon= — прогноз на 5 дней
GET /locations — список сохранённых точек (требуется токен)
POST /locations — сохранить точку (требуется токен)
DELETE /locations/{id} — удалить точку (требуется токен)
GET /alerts — список алертов (требуется токен)
POST /alerts — создать алерт (требуется токен)
POST /push/subscribe — подписка на уведомления (требуется токен)
